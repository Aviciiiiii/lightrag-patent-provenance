# 01 Baseline index and QA (dot's round2, 2026-10-29)

## Purpose
Build a LightRAG index over 20 patents and compare `naive` and `mix` on 10 baseline questions and 1 natural cross-chunk supplementary question (Q11), to see where document identity, claim location and source presentation go wrong.

## Setup (this experiment is the baseline; later experiments describe their differences from it)
- LightRAG v1.5.7, unmodified; `ainsert(texts, ids=<publication number>, file_paths=<publication number>.txt)`; JSON KV + NanoVectorDB + NetworkX.
- Chunking 1200/100 (o200k_base) → 48 chunks; extraction `entity_extract_max_gleaning=0`, LLM output cap 3500, temperature 0, thinking off, no retries.
- Queries: `aquery_llm` (answer and structured evidence saved from the same call), `include_references=True`, `top_k=12`, `chunk_top_k=8`, entity/relation/total tokens 2000/2000/8000, rerank off, one strict citation `user_prompt` for all questions.
- Supplements: `retrieval_probe.py` records the vector rank of the target chunks; `budget_sensitivity.py` raises the budgets on the same index to the order of the source defaults (40/20/6000/8000/30000) and asks Q06 and Q11 again.
- All parameters: [`evidence/full_settings.json`](evidence/full_settings.json), [`evidence/budget_sensitivity_settings.json`](evidence/budget_sensitivity_settings.json). Questions: [`../../data/round1/results/questions.json`](../../data/round1/results/questions.json), [`evidence/optional_question11.json`](evidence/optional_question11.json).

## Analysis and factors ruled out
- **Not glue code failing to pass sources**: `ids` and `file_paths` were passed at insertion; entities and relations carry `file_path` and `source_id` in storage and in the structured result (see AUDIT e1).
- **Not a loss at index time**: the target chunk vectors of Q06 and Q11 are in the index, they just rank low (`evidence/retrieval_rank_probe.json`).
- **Not an extraction failure** (Q11): the registration capabilities were extracted, merged and retrieved; the loss happens when the context for the model is assembled (P1, a design trade-off).
- **The Q11 misattribution occurred once**: 02 replayed the same context 3 times without repeating it, and neither rerun repeated it; it is not treated as a stable result.
- The truncation (P4) comes from the 3500 output cap of this setup, not from a LightRAG defect; LightRAG logs the truncation and drops the incomplete line.
