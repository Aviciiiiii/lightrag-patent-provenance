# Reproducibility: original run / 2026-11-05 / 2026-11-15

All three runs used the same code (LightRAG v1.5.7, unmodified), the same model (SiliconFlow `deepseek-ai/DeepSeek-V4.1-Flash`, temperature 0, thinking off; embedding `BAAI/bge-m3`), and the same parameters and inputs. They differ only in when they ran and who ran them:
- **original**: dot's original run (2026-10-29/30), the basis of the original reports.
- **20261105**: second run, on 2026-11-05, by the author on their own machine with dot's 11-05 adapted scripts; results in each experiment's `results_rerun_20261105/`.
- **20261115**: third run, on 2026-11-15, by Claude Code with the author's authorisation, using this repository's `run.sh live`; results in `results_rerun_20261115/` (with `RUN_RECORD.md`). Complete logs and LightRAG working directories are kept only in the local `runs/`.

Behavioural measures are scored with one rubric, [`SCORING_RUBRIC.md`](SCORING_RUBRIC.md): a rule decides each judgment. On the original run the rubric agrees with dot's original labels **242/242**. The 15 judgments where the rule was uncertain or differed from the original run (7 on 11-05, 8 on 11-15) were reviewed first by Claude Code and then by the author on 2026-11-15 (**human review**); both agreed on all 15, and they are marked “reviewed by the author” in the score files. All other judgments are rule-based and marked “rule only, not reviewed item by item”. Item-level details are in [`scoring/`](scoring/); the human review is recorded in [`scoring/HUMAN_REVIEW.md`](scoring/HUMAN_REVIEW.md) and `scoring/human_review_*.json`. The tables under “Item-by-item comparison” are generated by `python tools/build_reproducibility.py --write docs/REPRODUCIBILITY.md` (which includes every scored rerun).

## Summary

| | Consistent with the existing conclusions | Not consistent |
|---|---|---|
| Structural | **P1 sources removed**: in all three runs, 0 entity/relation lines in the extended-budget Q11 mix prompt carry `file_path`, while all records of the structured result do. **P7**: no claim entities in any of the three graphs. **P6 same-name merging across patents** occurs in all three (38/612, 31/642, 34/602 multi-source nodes) | Which nodes are merged varies: the example “Token” (an anonymisation substitute juxtaposed with a query token) is merged from the same 3 patents in the original and 11-15 runs, but **comes from only 1 patent on 11-05**; “Tokens” is the same in all three. 29 multi-source nodes occur in all three graphs |
| Behavioural: experiment 01 | 9/10 in both modes; at the baseline budget Q06 lacks the text and fails in both modes, and completes with the extended budget; Q11 still does not retrieve the text with the extended budget. The vector ranks of the target chunks are **identical** in all three runs (Q06 ranks 9 and 11; Q11 ranks 29 and 30) | **The Q11 “different patent family” misattribution occurs only in the original run** (1/26, 0/26, 0/26) |
| Behavioural: experiment 02 | **Identical** in all three: right patent 0/3, 3/3, 3/3; claim task completed with evidence 0/3, 0/3, 3/3; citation-number conflict in condition C 3/3; misattribution in the answer text 0/9; mid-sentence split 0/3, same chunk 3/3 | — |
| Behavioural: experiment 03 | F05 and F04 keep the target predicates under both boundaries (3/3 and 3/3 in every run); mix retrieves all target text 18/18; mix, naive and forced core answers 18/18 in all three runs; every run has extraction truncations (all in F01's same-chunk condition) | **F01's boundary effect is unstable**: the cross-chunk condition kept the predicate 0/3 → 1/3 → 3/3. There are 4 clean pairs (no truncation on either side) in total; 3 are “kept same-chunk, lost cross-chunk”, and the one pair of 11-15 kept it on both sides. **P8** (naive states a wrong claim dependency) occurs only in the original run; on 11-15 two naive answers list “claim 4 → claim 5 → claim 8” as a technical chain without calling it a dependency order, which is not counted |

**Possible reasons (not verified)**:
- Temperature 0 does not guarantee determinism, and the provider offers no seed. Extraction output differs slightly from run to run, so the three graphs have different node counts (612/642/602), and the target-patent entities retrieved for Q11 go from 5 to 3 and 2.
- One-off phenomena that depend on extraction or generation (the misattribution, P8, F01's missing predicate) therefore come and go.
- Phenomena determined by code (P1) or mainly by retrieval ranking (Q06 missing text) are stable in every run.
