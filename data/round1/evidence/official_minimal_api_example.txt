The matching REST route /query uses aquery_llm. /query/data instead invokes
rag.aquery_data(question, param), which omits answer generation but may still
need keyword extraction and embedding model calls. Do not describe /query/data
as a model-free endpoint. For REST /query, include_references=true and
include_chunk_content=true enrich each document reference with its chunk array.
include_chunk_content is not a valid QueryParam field in this exact version.
